Passive Event Listeners

Adding { passive: true } to scroll/touch listeners tells the browser you will never call preventDefault(), allowing it to start scrolling immediately without waiting for your handler to finish — eliminating scroll jank.

Without passive Browser waits for handler before scrolling.
Even an empty handler adds latency.
{ passive: true } Browser scrolls immediately.
Handler runs asynchronously in parallel.

The scroll box above uses a passive listener. Open DevTools → Performance to verify there are no "Forced Reflow" or scroll blocking warnings.
