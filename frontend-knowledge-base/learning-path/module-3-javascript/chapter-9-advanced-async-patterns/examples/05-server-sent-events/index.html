Server-Sent Events (SSE)

Chapter 9 · Advanced Asynchronous Patterns

What This Example Demonstrates

  • The SSE wire format: data:, id:, event:, retry:
  • Using EventSource to consume a live stream
  • Listening for named event types with addEventListener
  • Handling connection state and auto-reconnect behaviour
  • Closing the connection with eventSource.close()
  • A simulated SSE server running inside a SharedWorker / BroadcastChannel
Note: A real SSE stream requires a server that keeps the HTTP connection open and writes text/event-stream responses. Because this example runs entirely in the browser, we simulate the server with a ReadableStream piped through the Fetch API (using a Service Worker to intercept the request) so that the EventSource code is 100% authentic.

SSE Wire Format

# Comment lines start with ':'
: heartbeat

# Minimal event — only data field
data: Hello, world!

# Named event with ID
id: 42
event: stock-update
data: {"symbol":"AAPL","price":189.45}

# Multi-line data (lines are joined with \n)
data: {"part1":"Hello,
data:  World!"}

# Retry interval override (ms)
retry: 3000

EventSource API Reference

MemberDescription
new EventSource(url, options)Opens SSE connection. options.withCredentials sends cookies.
.readyState0 CONNECTING · 1 OPEN · 2 CLOSED
.urlThe URL of the SSE endpoint.
message eventFires for events with no event: field.
open eventConnection established.
error eventConnection error or server close (auto-retries).
addEventListener(type, fn)Listen to named event types (e.g. stock-update).
.close()Permanently close — no auto-reconnect.
