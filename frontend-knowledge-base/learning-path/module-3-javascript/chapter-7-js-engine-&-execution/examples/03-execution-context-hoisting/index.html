Execution Context & Hoisting

Explore how JavaScript processes code during the Creation Phase (hoisting) before executing it.

Execution Context Lifecycle

Global Execution Context
Creation Phase
  • Set up scope chain
  • Hoist var → undefined
  • Hoist function declarations (full body)
  • Bind this → window
Execution Phase
  • Run code line by line
  • Assign values to variables
  • Call functions → new Function EC created

var

var Hoisting

console.log(x); // ???
var x = 10;
console.log(x); // ???

Creation Phase: var x is hoisted and initialized to undefined.

Execution Phase: First log runs → undefined. Then assignment → x = 10. Second log → 10.

let/const

Temporal Dead Zone

try {
  console.log(y); // ???
} catch (e) {
  console.log(e.message);
}
let y = 20;
console.log(y); // ???

let/const are hoisted but NOT initialized. Accessing them before declaration is a ReferenceError — the TDZ (Temporal Dead Zone).

function

Function Declaration Hoisting

// Called BEFORE declaration — works!
sayHello();

function sayHello() {
  console.log("Hello, World!");
}

// Still works after too
sayHello();

Entire function declarations (name + body) are hoisted during the Creation Phase. The function is fully available before its definition in source code.

expression

Function Expression Hoisting

try {
  greet(); // ???
} catch (e) {
  console.log(e.constructor.name + ': ' + e.message);
}
var greet = function () {
  console.log("Hi!");
};
greet(); // ???

Only var greet is hoisted (as undefined). The function body is NOT hoisted. Calling undefined() throws a TypeError.

arrow

Arrow Function Hoisting

try {
  sayBye(); // ???
} catch (e) {
  console.log(e.constructor.name + ': ' + e.message);
}
const sayBye = () => {
  console.log("Bye!");
};
sayBye(); // ???

Arrow functions assigned to const are in the TDZ. Accessing before declaration → ReferenceError.

var

var Leaks Out of Blocks

if (true) {
  var leaked = "I escaped the block!";
  let blocked = "I stay in the block";
}
console.log(leaked);  // ???
try {
  console.log(blocked); // ???
} catch (e) {
  console.log(e.message);
}

var is function-scoped, not block-scoped. It leaks out of if, for, and while blocks. let/const are block-scoped.

Classic Hoisting Gotcha: var in Loops

❌ var in loop — broken closure

const fnsVar = [];
for (var i = 0; i < 3; i++) {
  fnsVar.push(function () {
    return i; // 'i' is shared — all see final value!
  });
}
// All return 3, not 0, 1, 2!
fnsVar.map(fn => fn()); // [3, 3, 3]

✅ let in loop — correct closure

const fnsLet = [];
for (let j = 0; j < 3; j++) {
  fnsLet.push(function () {
    return j; // each iteration gets its own 'j'!
  });
}
// Correctly returns 0, 1, 2
fnsLet.map(fn => fn()); // [0, 1, 2]
