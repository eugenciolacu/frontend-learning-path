JIT Compilation & Type Consistency

See how V8's JIT compiler optimizes type-consistent code and deoptimizes when types change.

How V8 Decides to Optimize

Step 1 Parsing

Source code → Abstract Syntax Tree (AST)

Step 2 Ignition (Bytecode)

AST → bytecode, executed immediately. Fast startup.

Step 3 TurboFan (JIT)

"Hot" functions compiled to optimized machine code. Assumes consistent types.

Deopt Deoptimization

Type assumption violated → falls back to bytecode. Performance drops.

Performance Benchmark

Run two versions of a function: one with consistent types (optimizable) and one with mixed types (deoptimized).

Code Examples

✅ Optimizable — Type-Consistent

// V8 sees 'number + number' every time.
// After warming up, TurboFan compiles this
// to highly optimized native machine code.

function addNumbers(a, b) {
  return a + b;
}

for (let i = 0; i < 5_000_000; i++) {
  addNumbers(i, i + 1); // always numbers ✅
}

⚠️ Deoptimizable — Mixed Types

// V8 optimizes for numbers first,
// then hits a string → deoptimizes!
// Bails out back to interpreted bytecode.

function addAny(a, b) {
  return a + b;
}

for (let i = 0; i < 4_999_999; i++) {
  addAny(i, i + 1);       // numbers...
}
addAny("hello", " world"); // string! 💥 deopt

✅ Object Shape Consistency

// V8 creates a "hidden class" for objects
// with the same shape. Consistent shapes
// allow V8 to use fast property access.

function createUser(name, age) {
  return { name, age }; // always same shape ✅
}

// V8 generates the same hidden class each time
const u1 = createUser("Alice", 30);
const u2 = createUser("Bob", 25);

⚠️ Object Shape Inconsistency

// Different property order = different
// hidden classes = slower property access

const obj1 = { x: 1, y: 2 };
const obj2 = { y: 2, x: 1 }; // different hidden class!

// Also bad: adding properties dynamically
const obj3 = {};
obj3.x = 1;  // hidden class change
obj3.y = 2;  // hidden class change again

Best Practices for JIT-Friendly Code

  • ✅ Keep function argument types consistent across all call sites
  • ✅ Initialize all object properties in the constructor (same order, same shape)
  • ✅ Avoid deleting object properties (delete obj.prop changes hidden class)
  • ✅ Prefer typed arrays (Int32Array, Float64Array) for numeric data
  • ⚠️ Avoid arguments object in hot functions — use rest parameters instead
  • ⚠️ Avoid try/catch in very hot inner loops — move them outside
  • ⚠️ Avoid eval() — prevents many optimizations
