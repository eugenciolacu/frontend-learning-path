4. CORS — what it is and how to deal with it

Cross-Origin Resource Sharing (CORS) is a browser security policy that blocks requests to a different origin (protocol + domain + port) unless the server explicitly allows it via response headers.

Signs you have a CORS problem:
Access to fetch at 'https://other-api.com/data' from origin 'https://myapp.com' has been blocked by CORS policy: No 'Access-Control-Allow-Origin' header…

CORS only applies in browsers. Server-to-server requests (Node.js, Python, etc.) are never subject to CORS.

Solutions:
  • If you own the API: Add Access-Control-Allow-Origin response headers.
  • If you don't: Route requests through your own backend proxy.
  • During development: Use Vite's server.proxy or webpack's devServer.proxy.
  • Using public APIs: Choose ones that already include CORS headers (PokeAPI, JSONPlaceholder, Open-Meteo…).
